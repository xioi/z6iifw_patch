# NLOG8：实验性仿 N-Log Picture Control

NLOG8 是面向 Z6II 8bit 内录的自定义 Picture Control 原型。它只改变亮度响应，不是尼康真正的 Rec.2020/N-Log 色调模式，也不保证可直接套用官方 N-Log 还原 LUT。

## 当前版本

| 版本 | 文件 | 用途 | 状态 |
| --- | --- | --- | --- |
| NLOG8 v01 | `sd/PICCON10.NCP` | 保留较接近原始 N-Log 码值的初版 | 真机可导入，中间调调色方向可用；高光和阴影码值范围不足 |
| NLOG8 v02 | `sd/PICCON11.NCP` | 扩展 8bit 两端可用码值，降低后期拉伸幅度 | 文件和数学响应已验证；待真机并排测试 |

```text
NLOG8 v01 SHA-256：10843b02ab1ffab75bc9d776170cee33d80849f537de2df437298299823d7770
NLOG8 v02 SHA-256：30500d5aa5eb3db76928ca7428496233ac4bae0373af7cba1a978778b7112179
```

两个文件均为 638 字节，使用 Neutral/RawLinear 补偿、256 项 LUT，锐化和饱和度为 0。对应 `.json` 报告记录模板哈希、参数和采样值。

## v01 真机结果

`nlog_test/nlog1.jpg` 为低反差原片截图，`nlog2.jpg` 为调色后截图。它们证明曲线可以导入并用于视频，调色后的色彩方向基本合理，但也显示两端过于受限：

- 原片没有亮度超过 200 的像素，高光上限明显偏低；
- 原片约一半画面亮度低于 48，黑位又垫在约 24 附近，暗部灰闷；
- 调色后约 37.3% 的像素亮度不超过 16，阴影被明显压死；
- 调色后没有大面积超过 235 的高光，主要问题不是全白硬裁切，而是原片两端码值不足、后期拉伸过强。

这些统计来自两张 JPEG 截图，不等同于完整视频波形或色带测试，不能据此判断所有场景。

## v02 的调整

v01 在模板实际输入范围内约使用 PC 码值 `33–181`：中间灰为 93，阴影约 60 个码值，高光约 88 个码值。

v02 保留相同的基础补偿、灰点增益和 N-Log 正向曲线，只在曲线输出端重新分配码值：

- 数学黑位锚点映射到 PC 码值 8；
- 最大线性 RAW 输入映射到 PC 码值 242；
- 18% 灰对应 PC 码值约 104；
- 模板实际最低输出约为 10。

因此阴影分配增至约 94 个码值，高光增至约 138 个码值，均比 v01 增加约 57%。中间灰从 93 提升到 104，是为了 8bit 可用性做出的曝光妥协，不再追求逐码值模拟 N-Log。

## 曲线生成方法

使用 [NikonPictureControlsDev](https://github.com/horshack-dpreview/NikonPictureControlsDev) 的 `Horshack_RawLinear.NCP` 作为数学模板。该模板用于补偿 Neutral 基础曲线及 sRGB 1/2.4 gamma；生成器保留其容器和输入响应，把每个线性 RAW 输出值送入尼康官方 N-Log 正向公式。

为对齐中间灰，线性值先乘以 `0.18 / 0.088`，把尼康测光的 8.8% 场景亮度映射到 N-Log 的 18% 反射率。然后计算：

```text
y < 0.328:
x = 650 × (y + 0.0075)^(1/3)

否则:
x = 150 × ln(y) + 619
```

`x` 为 10bit N-Log 全范围码值。v01 直接量化到 NCP 的 15bit 输出 LUT；v02 再按上述黑位和白位锚点扩展输出。18% 灰的原始正向结果为 `x=372.032`。

参考：[N-Log 官方参数](https://download.nikonimglib.com/archive5/x8yZX00KKy8505VK2Hn94bPDap74/N-Log_Specification_(En)01.pdf)、[Picture Control 曲线说明](https://nikonimglib.com/npcu/onlinehelp/en/pc010000.html)。

## 导入相机

不需要更新加载器或替换 `Z62APP.BIN`。

1. 在第一存储卡上创建 `NIKON/CUSTOMPC/`。
2. 同时复制 `PICCON10.NCP` 和 `PICCON11.NCP` 到该目录；已有同名旧文件先删除再复制。
3. 进入「管理优化校准 → 载入/保存 → 复制到照相机」，把 `NLOG8 v01` 和 `NLOG8 v02` 保存到不同自定义槽位。
4. 在视频拍摄菜单的「设定优化校准」中选择待测版本。
5. 使用 1080p24/25、固定白平衡和手动曝光；关闭自动 D-Lighting，先不要使用自动 ISO。

如果相机拒绝导入，请从这台 Z6II 导出一个本机生成的自定义 NCP，保留为后续适配模板。

## v01/v02 并排测试

1. 固定机位、焦距、曝光、ISO 和白平衡，连续录制两个版本。
2. 场景同时包含灰卡、暗部纹理、高光渐变和彩色物体。
3. 先比较未调色画面：v02 应具有更深的黑位和更高的高光上限，中间调略亮。
4. 调色时匹配中间灰，再比较阴影可恢复程度和高光过渡；不要盲目对两个版本套用同一个 LUT。
5. 检查暗部色带、饱和度高光和肤色。若 v02 色彩发生明显偏移，需要下一步拟合色彩参数，而不是继续拉伸曲线。

保留相机固件版本、NCP 哈希、视频规格、ISO、曝光、白平衡和原始短片。当前只有截图，后续若能提供同场景原视频，可进一步分析码值分配和压缩色带。

## 还原 LUT 评估

v01 的还原需要较大的两端拉伸，容易压黑并放大高光色带，不适合作为最终 LUT 目标。v02 先改善原片码值分配，更适合后续生成专用的中性轴反向曲线。

即使 v02 真机效果改善，仍不能直接使用官方 N-Log 还原 LUT 证明兼容：当前配置没有实现 Rec.2020 原色和完整 N-Log 色彩管线。后续 LUT 应基于实际 v02 响应生成，并用灰阶和色卡验证。

## 其他限制

- 不能恢复基础管线已经裁切的高光，也不能凭空增加传感器动态范围。
- 8bit 全范围 Log 容易出现暗部色带和渐变断层。
- 自定义曲线会改变饱和度；当前没有做三维色彩拟合。
- RawLinear 模板对原厂 Neutral 曲线的补偿是第三方近似，最终效果必须真机校准。
- 当前二进制以第三方模板生成；正式公开分发前，建议改用 Z6II 本机导出的模板重新生成并验证。

## 重新生成

```sh
# v01
python3 tools/generate_nlog8_pc.py --version 1 \
  --template /path/to/Horshack_RawLinear.NCP \
  --output sd/PICCON10.NCP --report sd/PICCON10.NCP.json

# v02
python3 tools/generate_nlog8_pc.py --version 2 \
  --template /path/to/Horshack_RawLinear.NCP \
  --output sd/PICCON11.NCP --report sd/PICCON11.NCP.json
```

已有输出时，确认可以替换后添加 `--force`。生成器会锁定已审阅模板的 SHA-256，检查记录布局、LUT 位置和单调性。
