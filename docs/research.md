# 实验研究与验证记录

本页集中保存不属于稳定发布说明的研究成果、已知问题和验证边界。稳定功能的安装方法见项目根目录 `README.md`；完整实验过程、哈希与失败案例见[研究笔记](research-notes.md)。将功能列入发布配置不等于完成所有真机场景验收。

## 发布功能的已知边界

### 竖屏 UI

当前适配后屏拍摄信息、根界面触控、4×3 i 菜单、部分二级设置页和菜单内方向切换。以下问题已在提交 `7dab6f1` 对应组合模块上复现，仍不能视为已经解决：

1. 竖屏时，快门速度、ISO 等参数按钮可以触发，但调整页面仍为横屏。
2. 竖屏时，曝光补偿、ISO 物理按钮或放大画面触发的 UI 仍为横屏。
3. i 菜单二级子菜单底部「i 键返回，OK 确认」的形状与文字错位。

实体 MENU、回放及 EVF 的 i 菜单保持原厂方向。EVF 竖屏拍摄信息是独立实验路径，不放入当前稳定发布模块；QEMU 无法验证真实 EVF 输出。旧版自制直方图/水平仪曾导致花屏、假死和快门禁用，已停用，原生 DISP 与水平仪交还相机。

### 普通录像时长扩展

实现同步更新 writer、父录制任务和 UI 的时长状态，而不是只修改剩余时间显示。UI 使用 `min(真实值, 999分59秒)` 避免原厂 16 位秒数回绕，录像任务仍保留真实容量值。

ARM 状态链与 QEMU 组合加载已验证，但现有记录**不能证明真机可稳定录制超过 29:59**。原厂 ROM 直改时长表会立即报告「录制已中断」，该方案已移除。`gphoto2 --set-config movie=1` 的 `--m--s` 显示也不会解除后台原厂计时。

### 视频方向元数据

普通 MOV/MP4 开档锁定姿态，分段重新读取，写入视频轨方向矩阵。QEMU 重定位、ARM 回调和组合加载通过；姿态 1/2/3 分别写入 90°/270°/180° 矩阵，姿态 0/4 保持原厂矩阵。Z7II 上游已有真机样片验证，但当前记录中 **Z6II 真机 MOV/MP4 文件验证仍未完成**。机内回放保持原厂横向显示，电脑播放器必须支持方向矩阵。

检查方式：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream_side_data=rotation \
  -of default=noprint_wrappers=1 /path/to/video.MOV
```

## 其他研究成果

| 方向 | 当前结果 | 尚未解决的问题 |
| --- | --- | --- |
| 手动对焦属性与距离 | 确认属性 `0x2000` 随对焦环变化，可记录原生绘制数据 | 具体距离换算、标尺位置和重叠清除尚未完成；[诊断说明](focus-distance.md) |
| 仿 N-Log 8bit Picture Control | `NLOG8 v01/v02` 使用官方正向曲线的 256 项 LUT 近似，已完成同场景真机比较 | 不是原厂 N-Log ISP，也不提供机内 10bit；[说明](nlog8-picture-control.md) |
| RAW12 单帧与有限连拍 | CPU 单帧、XDMAC＋CPU 单帧、DMA 双帧、8 帧有限写入均有真机结果；SD 与 CFexpress B 均写出分批 16 帧并导出有效 DNG | 连续 30fps 未实现；16 帧有 20–22 个通知缺口和重复源帧；DNG 色彩矩阵未校准 |
| 写卡性能 | 旧基准的 SD / CFexpress B 数据阶段为 36.315 / 16.088 MB/s；三档分组写基准已通过 QEMU 逐字节校验 | 真机分组写、缓存与文件调用耗时尚待对照，不能由卡标称速度推断持续带宽 |
| Magic Lantern 架构对照 | 已核实双源缓冲、帧槽状态、DMA、连续帧组写入和真实写速估算等机制 | 佳能无损压缩依赖原厂硬件 JPEG/RAW 路径，不能直接照搬地址；尼康等价可复用路径尚未确认 |
| PTP 与固件研究 | 保留 PTP、固件解密、K8 恢复和 QEMU 研究的详细过程 | 不作为终端安装依赖；[研究笔记](research-notes.md) 与[第三方仓库说明](third-party-repos.md) |

## 构建与验证

模块可通过 `z62_extensions/tools/build.py` 按参数组合。当前 `release/Z62APP.BIN` 使用：

```sh
python3 z62_extensions/tools/build.py \
  --portrait --movie --video-rotation \
  --output release/Z62APP.BIN --force
```

EVF、对焦诊断、RAW12 和写速基准等实验开关不进入该稳定发布模块。参数依赖、开发构建及 Release 打包见[构建指南](building.md)。

`tools/build_loader_firmware.py` 是面向终端用户的固定版本加载器生成器，内置原生 host 机器码与容器变换数据，不读取 K8 或外部密钥文件。它只接受哈希匹配的原厂 Z6II C 1.70 更新包，输出固定的已签名加载器；如果修改了 host 源码，仍须通过开发链重新构建和验证，不能沿用固定输出哈希证明新代码有效。

QEMU 能验证宿主启动、模块读取、重定位、回调安装和部分 GUI/录像路径，但不能替代真机 EVF、存储介质、视频文件、触控或长期录制验证。所有成功与失败的复现步骤统一保存在[研究笔记](research-notes.md#可复现验证的记录规范)，不把局部结果写成完整功能成功。
