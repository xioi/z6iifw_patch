# 研究笔记：Z6II 模块加载器与录像时长

## 录像限制的实际状态链

原厂普通录像的时长常量是 `1799000` 毫秒（29:59）。Z7II 的开源实现并不是单纯修改剩余时间显示，而是在录像任务启动时更新三类状态：

- writer 配置的 `+0x5c` 时长字段；
- 父录制任务的 `+0x5c` 时长字段；
- 两套 UI 配置的 `+0xd0` 总时长字段，并发送原厂刷新消息。

时长来自原厂容量计算函数，保留存储卷、预留空间、文件数量和码率转换限制。4K 50/60p 另有帧组预算，需要单独处理。

## 已失败的 ROM 直改方案

Z6II 的 ROM 查表函数 `0x10478240` 使用与 Z7II 相同的配置索引算法，表项位于主模块偏移 `0x19cb760`、`0x19cb808`、`0x19cb8b0`。把 96 个 `1799000` 改为更大值会改变菜单预计时间，但真机开始录像立即报告“录制已中断”。99:59:59 和 9:59:59 两个版本均失败，因此不是单纯数值溢出问题，而是没有同步完整录制状态。不要继续发布该直改表固件。

## Z6II 原生 SD 加载器

加载器移植自 [JKWTCN/z7ii-extensions](https://github.com/JKWTCN/z7ii-extensions)，保留其模块校验、重定位、缓存同步和常驻分配机制，做了以下 Z6II 适配：

- 只保留一个启动 Hook，不包含 Z7II 的网格、竖屏等无关 Hook；
- 启动位置 `0x1045063c`，宿主代码追加到 `0x125147b8`；
- 在 BSS 前原有的 8 个对齐字节中存放状态指针对：`0xc18aedb8`；
- 等待应用状态 `0xc1811e50` 的就绪字段，再依次尝试读取 `B:\Z62APP.BIN` 和 `A:\Z62APP.BIN`；
- 模块魔数改为 `Z62M`，目标标识为 `0x01700062`，避免误载 Z7II 模块；
- 保留加载状态和模块返回值，便于 QEMU/调试器诊断。

Z7II 与 Z6II 的 RAM 不能统一加一个偏移。例如启动参数、应用状态和录像 UI 配置分别存在不同的额外位移；所有函数均通过原始镜像的字节匹配、调用关系和字面量池逐项核对。

## Z62APP.BIN 格式

64 字节小端头，后接 Thumb 镜像和重定位表。头包含魔数、ABI、目标、文件尺寸、镜像尺寸、BSS 尺寸、入口偏移、重定位数量和 CRC32。加载器将镜像分配到 64 字节对齐内存，把绝对内部指针加上运行时基址，清理指令缓存后调用 `z62_main`。模块返回非零时释放内存，不保留回调。

当前录像模块使用位置无关代码，没有运行时内部绝对重定位项；两个任务回调通过 PC 相对地址取得。

## 竖屏 UI 移植

竖屏模块复用 Z7II 的 `portrait_menu.c`、`portrait_probe.c` 和直方图实现，但不移植网格等其他插件。当前版本默认开启，不包含 Z7II 的扩展设置菜单和配置文件；实体 MENU、回放与 EVF 保持原厂方向。

地址通过代码指令、ROM 指针数组和运行时对象三条路径核对。关键对应包括：图形分发 `0x1054ba99 → 0x1054e7a9`、方向读取 `0x103d4097 → 0x103d67f3`、导航表 `0x123be178 → 0x123c5e24`、字体表 `0x120687d4 → 0x120791f4`。RAM 不使用统一偏移，例如显示输出地址由同结构基址推导为 `0xc181d3cc`。

QEMU 中正式初始化返回 0，图形分发、GUI 更新、触控、导航和 i 菜单切换槽均指向正确模块函数。使用编译期强制方向的临时测试模块分别验证了左右两种竖屏；LCD 截图确认拍摄信息和 4×3 i 菜单实际旋转。临时测试模块未进入发布目录。

后续根据真机反馈把顶部信息条从整排缩放改为左右半排分行，保持原图标和字号。行内位置不压缩，行起点间隔为 64 像素；已验证双列布局、i 菜单和切换到精简 DISP 后的清除过程。截图见 `images/z62-portrait-rows.png`。

EVF 支持是独立实验分支，仅覆盖拍摄信息，不旋转 EVF 的 i 菜单。实现同时检查输出场景，并在 LCD/EVF 切换时触发原厂刷新。当前 QEMU 不提供可用 EVF 画面，因此该路径必须真机验证。发布目录只保留一种默认模块配置；需要 LCD-only 回退时，通过 `build.py --portrait --movie` 重新生成，不再保留独立预编译副本。

## 竖屏触控与菜单刷新修正

- 拍摄页触控此前被 i 菜单触控 Hook 排除。现在按 `relocate_live` 的各条规则生成逆映射候选点，再执行正向映射核对；屏幕外候选点直接拒绝，避免负坐标落入原厂左侧控件分支。触屏开关、快门速度、光圈和 i 按钮已逐点通过 ARM 调用验证。
- 普通二级设置页的原厂选项区为横向 `60–660`，旧实现把它缩到 `40–440`。现在将内容区扩展到 `0–480`，全宽背景单独裁剪，底部操作提示保留原布局，触控逆映射同步更新。
- 菜单方向变化不能只修改 `layout_orientation`，也不能只调用拍摄页的 `0x10557a09`。当前在 i 菜单和三个外部设置对象的原更新回调前检查方向，变化时通过各自 `+0x18` 事件入口发送事件 `2`，再执行原更新函数。事件 `0/1` 会退出菜单，不能用作刷新。
- 已核对的更新入口为 i 菜单 `0x105c3785`、Picture Control `0x1058f3d1`、色彩设置 `0x105b8679` 和详细设置 `0x1065c4e7`；对应事件入口为 `0x105c4c1d`、`0x1059445b`、`0x105b8617`、`0x1065c46b`。初始化同时检查更新槽和事件槽，不匹配则不加载。
- QEMU 已验证 i 根菜单、普通二级页和 Picture Control 在左竖屏、右竖屏与横屏之间完整重排，保留当前菜单层级和选中项。真机方向传感器与实际触摸仍待验证。

## 竖屏候选版真机问题（`7dab6f1`）

以下问题来自提交 `7dab6f1` 对应组合模块的真机测试，尚未修复：

1. 竖屏时，快门速度、ISO 等拍摄参数按钮可以触发，但弹出的调整页面仍为横屏。
2. 竖屏时，按下曝光补偿或 ISO 物理按钮，或放大画面后，出现的相关 UI 仍为横屏。
3. 进入 i 菜单的二级子菜单后，底部「i 键返回，OK 确认」的按钮形状与文字错位。

当前竖屏适配只覆盖拍摄主界面、i 根菜单及已知设置对象。前两项涉及的参数调整页和临时曝光/放大覆盖层需要单独识别与适配，不能直接套用现有普通设置页的映射。第三项的初步排查方向是底部提示文字与背景采用了不同的缩放路径，但尚未通过绘制记录确认根因。

## 视频方向元数据移植

实现来自 Z7II 上游提交 `e507523`（`sdk/movie_rotation.h` 和 `movie_rotation_shadows.h`）。它不重编码视频，而是在文件 mux 任务打开每个文件时读取机身姿态，在关闭文件、生成视频轨头部时替换 ISO 显示矩阵。录制中的后续转动不改变已开文件，原厂分段会重新读取姿态。

Z6II 对应关系经过原厂主模块字节匹配和实际指令核对：

- mux 任务槽 `0xc1f2d84c`，原生入口 `0x104e2141`；控制槽 `0xc1811550`，运行时控制块为 `0xc1f2d858`；
- 开档与分段函数分别为 `0x104e1eb1`、`0x104e1831`，轨道构建函数为 `0x1053ba7d`，方向读取为 `0x103d67f3`；
- 复制的 Task、Close、Header 分别位于 `0x104e2140`、`0x104e1694`、`0x1053c4bc`，尺寸为 `0x418`、`0x264`、`0x7c`；
- 三段 FNV-1a 校验分别为 `0x960f4921`、`0x12db7d0a`、`0x32842c20`。Header 与 Z7II 逐字节相同，Task/Close 只有已核对的调用编码及字面量差异；
- 原生结构保持文件表基址 `0x3f0`、步长 `0x88`、上下文偏移 `0x2c` 和矩阵偏移 `0x109`。完整调用地址表在 `z62_extensions/sdk/movie_rotation_shadows.h`。

初始化在安装其他 Hook 前检查任务槽、控制槽和三段代码哈希，不匹配则返回错误，不启用功能。复制代码保留原厂事件处理和文件写入，只把开档、分段和轨道构建调用改到模块回调。

QEMU 中独立方向模块及完整组合均返回 `LOADED=11`、模块返回 0；控制块和 mux 任务入口吻合，录像与绘图 Hook 可与方向功能共存。导出的运行时代码共 68 个调用及调用桩全部通过逐条核对，未修改的指令和字面量与原厂一致。ARM 仿真实际执行 `movie_rot_track`：姿态 1/2/3 分别写入 90°、270°、180° 的 36 字节大端矩阵，姿态 0/4 保持原厂数据，写入边界没有越界。

这些结果尚未覆盖 Z6II 真机 MOV/MP4 文件、机内回放和电脑播放器。机内回放仍按原厂横向显示；真机需要分别验证两种容器、不同开档方向及原厂分段。

## 自制直方图/水平仪的兼容性处理

视频和照片真机测试随后发现自制直方图/水平仪叠加会引起粉色像素块、假死和快门禁用。仅禁止视频模式执行采样不足以保证照片模式安全，因此当前所有模块已停用整段自制叠加逻辑，GUI 更新直接交还原厂实现。原生 DISP 和水平仪仍可使用，其他竖屏功能不受影响。后续如需恢复自制叠加，需要重新核对 Z6II 的采样对象、显示缓冲和页面生命周期，不能直接沿用 Z7II 实现。

## 验证边界

固件打包会执行原包 K8 验证、主模块 CRC、包 CRC、重签、重新解密和目录逐成员比对。QEMU 可验证启动、读卡、模块初始化和回调安装，但其录像编码与真实硬件计时不完整，不能据此宣称真机已突破 29:59。最终仍需真机录像验证。

## 其他已排除的方法

`gphoto2 --set-config movie=1` 虽可触发录像，但屏幕时间显示 `--m--s`，后台原厂计时仍照常运行，到 29:59 仍会自动停止；这不是破解路径。
