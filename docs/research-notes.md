# 研究笔记：Z6II 模块加载器与录像时长

## 录像限制的实际状态链

原厂普通录像的时长常量是 `1799000` 毫秒（29:59）。Z7II 的开源实现并不是单纯修改剩余时间显示，而是在录像任务启动时更新三类状态：

- writer 配置的 `+0x5c` 时长字段；
- 父录制任务的 `+0x5c` 时长字段；
- 两套 UI 配置的 `+0xd0` 总时长字段，并发送原厂刷新消息。

时长来自原厂容量计算函数，保留存储卷、预留空间、文件数量和码率转换限制。4K 50/60p 另有帧组预算，需要单独处理。

## 已失败的 ROM 直改方案

Z6II 的 ROM 查表函数 `0x10478240` 使用与 Z7II 相同的配置索引算法，表项位于主模块偏移 `0x19cb760`、`0x19cb808`、`0x19cb8b0`。把 96 个 `1799000` 改为更大值会改变菜单预计时间，但真机开始录像立即报告“录制已中断”。99:59:59 和 9:59:59 两个版本均失败，因此不是单纯数值溢出问题，而是没有同步完整录制状态。不要继续发布该直改表固件。

## Z6II 原生 SD 加载器

加载器移植自 [JKWTCN/z7ii-extensions](https://github.com/JKWTCN/z7ii-extensions)，保留其模块校验、重定位、缓存同步和常驻分配机制，做了以下 Z6II 适配：

- 只保留一个启动 Hook，不包含 Z7II 的网格、竖屏等无关 Hook；
- 启动位置 `0x1045063c`，宿主代码追加到 `0x125147b8`；
- 在 BSS 前原有的 8 个对齐字节中存放状态指针对：`0xc18aedb8`；
- 等待应用状态 `0xc1811e50` 的就绪字段，再依次尝试读取 `B:\Z62APP.BIN` 和 `A:\Z62APP.BIN`；
- 模块魔数改为 `Z62M`，目标标识为 `0x01700062`，避免误载 Z7II 模块；
- 保留加载状态和模块返回值，便于 QEMU/调试器诊断。

Z7II 与 Z6II 的 RAM 不能统一加一个偏移。例如启动参数、应用状态和录像 UI 配置分别存在不同的额外位移；所有函数均通过原始镜像的字节匹配、调用关系和字面量池逐项核对。

## Z62APP.BIN 格式

64 字节小端头，后接 Thumb 镜像和重定位表。头包含魔数、ABI、目标、文件尺寸、镜像尺寸、BSS 尺寸、入口偏移、重定位数量和 CRC32。加载器将镜像分配到 64 字节对齐内存，把绝对内部指针加上运行时基址，清理指令缓存后调用 `z62_main`。模块返回非零时释放内存，不保留回调。

当前录像模块使用位置无关代码，没有运行时内部绝对重定位项；两个任务回调通过 PC 相对地址取得。

## 竖屏 UI 移植

竖屏模块复用 Z7II 的 `portrait_menu.c`、`portrait_probe.c` 和直方图实现，但不移植网格等其他插件。当前版本默认开启，不包含 Z7II 的扩展设置菜单和配置文件；实体 MENU、回放与 EVF 保持原厂方向。

地址通过代码指令、ROM 指针数组和运行时对象三条路径核对。关键对应包括：图形分发 `0x1054ba99 → 0x1054e7a9`、方向读取 `0x103d4097 → 0x103d67f3`、导航表 `0x123be178 → 0x123c5e24`、字体表 `0x120687d4 → 0x120791f4`。RAM 不使用统一偏移，例如显示输出地址由同结构基址推导为 `0xc181d3cc`。

QEMU 中正式初始化返回 0，图形分发、GUI 更新、触控、导航和 i 菜单切换槽均指向正确模块函数。使用编译期强制方向的临时测试模块分别验证了左右两种竖屏；LCD 截图确认拍摄信息和 4×3 i 菜单实际旋转。临时测试模块未进入发布目录。

后续根据真机反馈把顶部信息条从整排缩放改为左右半排分行，保持原图标和字号。行内位置不压缩，行起点间隔为 64 像素；已验证双列布局、i 菜单和切换到精简 DISP 后的清除过程。截图见 `images/z62-portrait-rows.png`。

EVF 支持是独立实验分支，仅覆盖拍摄信息，不旋转 EVF 的 i 菜单。实现同时检查输出场景，并在 LCD/EVF 切换时触发原厂刷新。当前 QEMU 不提供可用 EVF 画面，因此该路径必须真机验证；发布目录保留 LCD-only 回退模块。

## 验证边界

固件打包会执行原包 K8 验证、主模块 CRC、包 CRC、重签、重新解密和目录逐成员比对。QEMU 可验证启动、读卡、模块初始化和回调安装，但其录像编码与真实硬件计时不完整，不能据此宣称真机已突破 29:59。最终仍需真机录像验证。

## 其他已排除的方法

`gphoto2 --set-config movie=1` 虽可触发录像，但屏幕时间显示 `--m--s`，后台原厂计时仍照常运行，到 29:59 仍会自动停止；这不是破解路径。
