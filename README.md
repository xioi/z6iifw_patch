# Z6II Firmware Patch

适用于 **Nikon Z 6II、C 固件 1.70** 的实验性 SD 原生模块加载器与扩展模块。项目移植自 [JKWTCN/z7ii-extensions](https://github.com/JKWTCN/z7ii-extensions)，并针对 Z6II 重新核对函数地址、数据结构、模块格式和固件打包流程。

[构建指南](docs/building.md) · [研究笔记](docs/research-notes.md) · [对焦诊断](docs/focus-distance.md) · [第三方仓库说明](docs/third-party-repos.md)

> [!WARNING]
> 本项目与尼康官方无关，目前仍是研究候选版，不是稳定、完整的固件破解方案。修改固件和运行原生模块可能导致死机、数据丢失、无法启动或硬件损坏。请备份数据，在可承担风险的前提下测试。
>
> **仅适用于 Z6II C 1.70。不要用于 Z5、Z6、Z7II、Z6III 或其他固件版本。**

## 功能与状态

| 功能 | 当前实现 | 验证状态 |
| --- | --- | --- |
| SD 原生模块加载 | 启动后读取并执行 `Z62APP.BIN`，支持模块校验、重定位和缓存同步 | QEMU 启动、读卡、加载及回调安装通过 |
| 参数化组合构建 | 通过构建参数选择竖屏、EVF、录像时长、视频方向和对焦诊断，只生成一个模块 | 功能依赖和单输出构建通过；完整组合 QEMU 加载通过 |
| 后屏竖拍 UI | 旋转拍摄信息和 4×3 i 菜单，同步根界面触控热区，适配部分二级设置页和菜单内方向切换 | QEMU 通过；真机仍有下述已知问题 |
| EVF 竖屏拍摄信息 | 实验性旋转 EVF 拍摄信息，处理 LCD/EVF 切换 | QEMU 无法验证 EVF；需真机确认 |
| 普通录像时长扩展 | 运行时同步 writer、父录制任务和 UI 时长状态；UI 最多显示 999 分 59 秒，录制状态保留真实值 | 状态链 ARM 验证通过；尚未确认真机可稳定超过 29:59 |
| 视频方向元数据 | 普通内录 MOV/MP4 开档锁定姿态，分段重新读取，写入视频轨显示矩阵 | QEMU 重定位和 ARM 回调通过；Z6II 真机视频文件待验证 |
| 手动对焦诊断 | 读取实时对焦位置属性 `0x2000`，记录原生绘制数据 | 已确认属性随对焦环变化；距离显示和标尺修正尚未完成 |
| 仿 N-Log 8bit Picture Control | `NLOG8 v01` 自定义 NCP，使用官方正向曲线的 256 项 LUT 近似 | 文件结构和数学响应已验证；真机导入、色调和色带待测试，[说明](docs/nlog8-picture-control.md) |

当前模块**不包含**旧版自制直方图/水平仪叠加；该实现曾在照片和视频页面引起花屏、假死与快门禁用，现已完全停用，原生 DISP 和水平仪交还相机处理。

## 下载与发布文件

预编译固件和默认配置模块不直接提交到 Git 源码仓库，应从项目的 **GitHub Releases** 获取与源码版本匹配的发布压缩包。发布包只保留一种模块配置：

| 文件 | 用途 |
| --- | --- |
| `firmware/Z6_2_0170_loader.bin` | 模块加载器升级固件，只需安装一次 |
| `firmware/Z6_2_0170_loader.bin.json` | 加载器构建、原包校验及回读验证报告 |
| `sd/Z62APP.BIN` | 默认发布配置：LCD 竖屏、EVF 实验、录像时长扩展和视频方向元数据 |
| `sd/Z62APP.BIN.json` | 模块配置、编译定义、哈希及完整构建报告 |
| `SHA256SUMS.txt` | 加载器和模块的 SHA-256 校验值 |

源码仓库默认忽略 `firmware/`、`sd/`、`artifacts/` 和二进制产物；因此 GitHub 自动生成的 Source code 压缩包不包含预编译文件。需要其他功能组合时，使用[构建指南](docs/building.md)重新生成同一个 `Z62APP.BIN`，不再维护 LCD-only、movie-only 或 diagnostics 等独立预编译副本。

## 安装

### 1. 安装模块加载器

1. 备份照片和 SD 卡内容，确保相机电量充足。
2. 将发布包中的 `firmware/Z6_2_0170_loader.bin` 复制到 SD 卡根目录。
3. 在相机中选择「设定菜单 → 固件版本 → 升级固件」，确认升级。
4. 升级完成后可删除 SD 卡根目录中的升级固件。

如果已经安装了相同校验值的加载器，不必重复刷机；后续更新只需替换 `Z62APP.BIN`。

### 2. 安装 SD 模块

1. 使用发布包中的默认配置，或按构建指南生成所需配置。
2. 删除 SD 卡根目录中已有的 `Z62APP.BIN`，再将新模块复制到根目录，文件名保持为 `Z62APP.BIN`。不要直接依赖覆盖写入。
3. 等待存储卡访问结束，关机后重新开机。加载器依次尝试 `B:\Z62APP.BIN` 和 `A:\Z62APP.BIN`。
4. 先检查横屏、左右竖屏、i 菜单、各 DISP 页面及照片/视频切换，再进行短录像测试。

`.json` 清单用于在电脑上确认配置，不必复制到相机。对焦诊断配置的使用和日志解析方法见[对焦诊断指南](docs/focus-distance.md)。

## 当前已知问题

以下问题已在提交 `7dab6f1` 对应的组合模块上通过真机复现，**尚未修复**：

1. 竖屏时，快门速度、ISO 等拍摄参数按钮可以触发，但弹出的调整页面仍为横屏。
2. 竖屏时，按下曝光补偿或 ISO 物理按钮，或放大画面后，出现的相关 UI 仍为横屏。
3. 进入 i 菜单的二级子菜单后，底部「i 键返回，OK 确认」的按钮形状与文字错位。

其他限制：

- 参数调整页和临时曝光/放大覆盖层尚未完整纳入竖屏适配；EVF 页面也需继续验证。
- 实体 MENU、回放界面及 EVF 的 i 菜单保持原厂方向，场景图像本身不会旋转。
- 100/120p 慢动作等特殊录像路径的独立限制不在当前模块目标内。
- 大容量卡的 UI 可录时长按 `min(真实值, 999 分 59 秒)` 发布，避免原厂 16 位秒数回绕；writer 和父录制任务仍使用真实容量，不在此处截短实际录制状态。
- 卡容量、文件数量、电池、过热保护仍然有效；预计可录时间不等于保证录制时间。
- 旧的 ROM 直改录像表固件会立即报告「录制已中断」，已移除，不应再刷。

## 视频方向元数据

`--video-rotation` 可独立使用，不依赖竖屏 UI 或录像时长扩展。普通内录 MOV/MP4 在每个文件开档时锁定机身姿态；录制中转动机身不会改变当前文件，原厂分段打开新文件时会重新读取姿态。该功能只修改视频轨的显示矩阵，不重编码或旋转实际像素。

机内视频回放仍使用原厂横向显示，电脑播放器也必须支持视频轨显示矩阵。真机测试应分别录制横屏和竖屏的短 MOV、MP4，在电脑上检查实际播放方向，并可用 FFprobe 查看旋转元数据：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream_side_data=rotation \
  -of default=noprint_wrappers=1 /path/to/video.MOV
```

Z7II 上游实现已有真机样片验证；Z6II 移植目前只完成构建、QEMU 和 ARM 回调验证，不能据此宣称真机文件已经通过。

## 回退与恢复

- **需要关闭 EVF 实验路径**：用 `--portrait --movie` 重新构建 LCD 竖屏＋录像配置。
- **只需要关闭视频方向写入**：保留其他参数并移除 `--video-rotation`，例如 `--portrait --evf --movie`。
- **只需要录像实验功能**：用 `--movie` 重新构建。
- **停用全部扩展模块**：删除 SD 卡根目录的 `Z62APP.BIN`，完整断电后重开；加载器仍在，但不会加载扩展。
- **恢复官方固件**：刷回尼康官方 Z6II C 1.70 升级包。官方固件需要自行获取，本项目不附带原厂固件。

切换配置时先删除相机 SD 卡上的旧模块，再复制新文件。如果模块导致异常，先关机并取出 SD 卡，再重新启动。不要在相机仍访问存储卡时拔卡。

## 当前候选版校验值

默认发布参数 `--portrait --evf --movie --video-rotation` 生成当前候选。历史无方向真机候选的哈希为 `cedba023…2942`；当前源码重新构建会因大容量 UI 限幅修正而产生新哈希。当前含方向默认模块只完成构建、QEMU 和 ARM 验证，尚未确认真机视频文件及大容量卡显示：

```sh
shasum -a 256 -c SHA256SUMS.txt
```

## 从源码构建

只构建 SD 模块不需要原厂固件或密钥。以下命令生成默认发布组合：

```sh
python3 z62_extensions/tools/build.py --portrait --evf --movie --video-rotation
```

输出为 `artifacts/Z62APP.BIN` 和 `artifacts/Z62APP.BIN.json`。切换到其他配置时，明确使用 `--force` 替换旧输出，例如：

```sh
# LCD 竖屏 + 录像，不含 EVF
python3 z62_extensions/tools/build.py --portrait --movie --force

# 仅录像时长扩展
python3 z62_extensions/tools/build.py --movie --force

# 仅视频方向元数据
python3 z62_extensions/tools/build.py --video-rotation --force

# 对焦诊断，自动包含 LCD 竖屏路径
python3 z62_extensions/tools/build.py --focus-probe --force
```

这些示例是互斥配置，不要依次执行后再误认为输出仍包含全部功能。完整参数、依赖关系、加载器构建和 Release 打包步骤见 **[构建指南](docs/building.md)**。构建签名升级包需要官方 C 1.70 更新包、匹配的解密表和 K8 签名材料，这些输入不随仓库提供。

## 验证边界

- 固件构建会检查原厂主模块 SHA-256、Hook 原指令、BSS 边界、模块 CRC、包 CRC、K8 签名及重新解密后的逐成员一致性。
- QEMU 已验证宿主启动、读卡、重定位、模块入口、回调安装，以及部分菜单的双方向旋转和触控坐标映射。
- QEMU 不提供完整 EVF、录像编码、硬件计时或真实触摸环境，不能据此宣称这些功能已在真机通过。
- 正式模块曾在 ARM/QEMU 环境返回 `LOADED=11`、模块返回 0；这只证明加载链路，不等同于长期稳定性。
- 视频方向移植已在 QEMU 验证运行时保护、mux 任务安装和 68 个调用/调用桩重定位；完整组合的竖屏、录像与方向 Hook 可同时安装。
- ARM 仿真已实际调用方向回调：姿态 1/2/3 分别写入 90°/270°/180° 的 36 字节矩阵，姿态 0/4 保持原厂矩阵；尚未验证 Z6II 真机 MOV/MP4 文件。
- 大容量显示修复的 ARM 状态链测试确认：UI 在 `59,999,000 ms` 处限幅，writer 和父任务仍收到未限幅容量；完整 QEMU 加载保持原厂竖屏 GUI 链及录像、视频方向 Hook。
- 各参数组合必须按自己的哈希和测试范围验收，不能沿用历史候选的真机结论。

## 源码结构

```text
z62_extensions/
├── host/                  # 启动 Hook、SD 模块加载器和链接脚本
├── plugins/               # 可条件组合的竖屏、录像和对焦诊断代码
├── sdk/                   # Z6II 地址、数据结构和模块 ABI
└── tools/                 # 参数化模块、宿主及升级包构建工具

decrypt_firmware.py        # 旧版尼康固件容器解密与校验
repack_firmware.py         # 模块替换、CRC 与 K8 重签
docs/                      # 构建、研究及诊断文档
patches/                   # 已失败方案和地址映射记录
tools/                     # PTP 与真机研究工具
```
