# 解除录像时长限制（29:59）

## 当前方案

使用 SD 原生模块在运行时替换录像任务与 UI 任务回调。录像开始时，模块根据所选存储卷的可用容量计算时长，并同时更新 writer、父录制任务和 UI 配置；原厂的容量、文件数量、过热及特殊录像模式保护逻辑保留。

- 加载器固件：`firmware/Z6_2_0170_loader.bin`
- SD 模块：`sd/Z62APP.BIN`
- 移植源码：`z62_extensions/`
- 原始实现：[JKWTCN/z7ii-extensions](https://github.com/JKWTCN/z7ii-extensions) 的 `sdk/movie_limit.h`

## 已排除：直接修改 ROM 时长表

Z6II 主模块中有 3 段、共 96 个 `1799000` 毫秒（29:59）表项：

| 段 | 主模块内偏移 |
|----|--------------|
| 1 | `0x19cb760` |
| 2 | `0x19cb808` |
| 3 | `0x19cb8b0` |

把这些表项改为 `359999000`（99:59:59）或 `35999000`（9:59:59）后，相机菜单会显示更大的预计可录时间，证明查表路径生效；但两种版本在真机开始录像时都立即报告“录制已中断”。**该方案不等价于运行时补丁，不可使用，旧固件已从发布目录移除。**

原因是录像开始路径还使用 writer 与父任务中的时长字段；只改 UI/默认表没有更新这些状态。当前模块方案显式处理这些字段。

## Z6II C 1.70 地址移植

以下地址均通过原版 Z7II/Z6II 主模块的函数字节、调用点及字面量池交叉核对，不使用全局固定偏移：

| 用途 | Z7II | Z6II |
|----|------|------|
| UI 任务回调槽 | `0xb2982114` | `0xc296e254` |
| UI 原厂处理函数 | `0x104584cf` | `0x1045aafb` |
| 录像任务回调槽 | `0xb1f5926c` | `0xc1f5926c` |
| 录像原厂处理函数 | `0x104a5aa3` | `0x104a83f3` |
| UI 配置 0 / 1 | `0xb2982160` / `0xb2982518` | `0xc296e2a0` / `0xc296e658` |
| writer / 父任务配置 | `0xb1f598c8` / `0xb1f59078` | `0xc1f598c8` / `0xc1f59078` |
| 录像状态基址 | `0xb188abd0` | `0xc188ab68` |
| 特殊录像/帧预算基址 | `0xb1811798` | `0xc18117a8` |
| 容量计算函数 | `0x1048fcfd` | `0x1049261d` |

特殊录像（例如 100/120p 慢动作）有独立的实际时间限制，本模块不以其为目标。解除普通录像时长后仍可能因卡满、过热或电池不足停止。
